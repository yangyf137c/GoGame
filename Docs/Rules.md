# Rules.md

## 1. 使用说明

本文件是核心玩法规则规格。Codex 实现规则时应优先参考本文件。

若某条规则标记为：

```text
[待定]
```

表示设计者后续可能修改。为了不阻塞 MVP 实现，该条目同时给出「默认建议」。Codex 在未收到新的设计确认前，应按默认建议实现。

## 2. 基础定义

### 2.1 阵营

- 黑方：`Black`，默认玩家方。
- 白方：`White`，默认电脑方。
- 无阵营：`None`，用于无归属或系统状态。

### 2.2 地图格

地图格是正方形网格中的一个逻辑单元。

每个地图格包含：

- 坐标。
- 地形类型。
- 资源产出类型。
- 资源产出值。
- 是否可放置棋子。
- 当前是否有棋子。
- 当前归属。

### 2.3 棋子

棋子是放置在地图格上的单位。

每个棋子包含：

- 所属方。
- 棋子类型。
- 所在坐标。
- 是否存活。
- 控制半径。

### 2.4 棋块 Group

同一阵营、互相连通的多个棋子构成一个棋块。

## 3. 坐标与邻接规则

### 3.1 坐标系统

- 逻辑坐标使用 `Vector2Int`。
- x 轴向右递增。
- y 轴向上递增。
- 地图外坐标无效。

### 3.2 邻接规则

[待定]

默认建议：所有棋块连通、气、提子判断均使用四方向邻接。

四方向邻接：

- 上：`(x, y + 1)`
- 下：`(x, y - 1)`
- 左：`(x - 1, y)`
- 右：`(x + 1, y)`

默认不使用斜向邻接。

可选方案：

- 方案 A：四方向邻接，推荐用于 MVP。
- 方案 B：八方向邻接，但会显著改变气和提子的策略复杂度。

最终选择：

```text
邻接规则：四方向邻接
```

## 4. 气规则

### 4.1 气的定义

一个棋块的气，是该棋块中任意棋子四方向相邻的空地图格数量。

默认规则：

- 空地图格计为气。
- 有己方棋子的格子不计为气。
- 有敌方棋子的格子不计为气。
- 地图外不计为气。
- 同一个空格被棋块内多个棋子相邻时，只计为 1 气。

### 4.2 单棋子示例

在无限平地中，一个没有相邻棋子的棋子有 4 气。

在地图边缘，地图外不计为气。

### 4.3 地形是否影响气

[待定]

默认建议：MVP 中，地形不影响气。只要地图格存在、没有棋子，就计为气。

可选方案：

- 方案 A：所有存在的空地图格都提供气，推荐用于 MVP。
- 方案 B：山峦不提供气。
- 方案 C：河流不提供气。
- 方案 D：某些地形提供特殊气数或阻挡连通。

最终选择：

```text
地形是否影响气：山峦河流不提供气。
```

## 5. 棋块规则

### 5.1 棋块形成

同一阵营棋子通过邻接规则连接时，形成同一棋块。

默认建议：

- 只使用四方向连接。
- 斜向接触不形成同一棋块。

### 5.2 棋块生命

一个棋块只要气数大于 0，即为存活。

一个棋块气数等于 0 时，处于无气状态，需要根据提子规则移除。

## 6. 放置棋子规则

### 6.1 基础合法性

一次放置棋子必须满足：

- 操作方是当前行动方。
- 目标格存在于地图中。
- 目标格 `IsPlaceable = true`。
- 目标格当前没有棋子。
- 当前方资源足够支付放置费用。
- 放置后按提子结算顺序处理，最终己方新棋块至少有 1 气。

### 6.2 是否允许在敌方占有地块落子

[待定]

默认建议：允许，只要目标格没有棋子且 `IsPlaceable = true`。

理由：占地归属是影响资源和胜负的状态，不直接等同于落子权限。这样能形成争夺和反打。

可选方案：

- 方案 A：允许在任何可放置且无棋子的地图格落子，推荐用于 MVP。
- 方案 B：只能在己方归属或无归属格落子。
- 方案 C：只能在友方棋子控制范围内落子。
- 方案 D：根据资源距离费用限制远距离落子，而不是直接禁止。

最终选择：

```text
敌方占有地块落子规则：根据资源距离费用限制远距离落子，而不是直接禁止。
```

### 6.3 是否允许远距离落子

[待定]

默认建议：允许远距离落子，但费用与最近友方棋子的曼哈顿距离成正比。

可选方案：

- 方案 A：允许任意距离落子，距离越远费用越高，推荐用于 MVP。
- 方案 B：只能在距离友方棋子一定范围内落子。
- 方案 C：只能在当前己方占有地块落子。
- 方案 D：当前方无棋子时只能在关卡指定出生点落子。

最终选择：

```text
远距离落子规则：允许任意距离落子，距离越远费用越高。
```

### 6.4 当前方没有任何棋子时如何落子

[待定]

默认建议：如果当前方没有任何棋子，则只能在关卡指定 `SpawnPoint` 或初始点落子。

可选方案：

- 方案 A：只能在出生点落子，推荐用于 MVP。
- 方案 B：允许任意可放置格落子，但收取固定费用。
- 方案 C：当前方没有棋子时直接失败。

最终选择：

```text
[待填写]
无棋子时落子规则：只能在出生点落子
```

## 7. 提子规则

### 7.1 无气则提

棋块气数为 0 时，该棋块中所有棋子应被从棋盘上移除。

### 7.2 提子结算顺序

[待定]

默认建议：落子后先检查敌方，再检查己方。

具体流程：

1. 临时放置新棋子。
2. 找到新棋子四方向相邻的所有敌方棋块。
3. 对每个敌方棋块计算气。
4. 气为 0 的敌方棋块立即移除。
5. 然后计算新棋子所在己方棋块的气。
6. 若己方棋块气为 0，则该操作非法并回滚。
7. 若操作合法，重新计算地图块归属。

可选方案：

- 方案 A：先提敌方，再检查己方，推荐用于 MVP，也接近围棋常见处理。
- 方案 B：同时检查双方无气棋块，再统一移除。
- 方案 C：只允许提敌方，不允许己方因落子被提。

最终选择：

```text
[待填写]
提子结算顺序：只允许提敌方，不允许己方因落子被提。
```

### 7.3 自杀手

[待定]

默认建议：不允许纯自杀手。若落子能先提掉敌方棋块，并使己方新棋块获得气，则该落子合法。

可选方案：

- 方案 A：不允许纯自杀手，推荐用于 MVP。
- 方案 B：允许自杀手，落子后己方无气棋块被移除。
- 方案 C：允许自杀手但需要特殊资源或特殊棋子。

最终选择：

```text
[待填写]
自杀手规则：不允许纯自杀手
```

### 7.4 同时无气情况

[待定]

默认建议：按「先提敌方，再检查己方」处理，因此不会出现真正的同时移除。若敌方被提后己方有气，则合法；否则非法并回滚。

可选方案：

- 方案 A：按结算顺序处理，推荐用于 MVP。
- 方案 B：双方无气棋块同时移除。
- 方案 C：当前行动方优先。

最终选择：

```text
[待填写]
同时无气处理：按结算顺序处理
```

### 7.5 是否存在打劫规则

[待定]

默认建议：MVP 不实现围棋打劫规则。

可选方案：

- 方案 A：不实现打劫，推荐用于 MVP。
- 方案 B：禁止立即重复上一棋盘状态。
- 方案 C：加入回合制专属冷却规则。

最终选择：

```text
[待填写]
打劫规则：不实现打劫
```

## 8. 占地规则

### 8.1 占地与气分离

占地只影响资源产出和胜负结算，不影响气的计算。

默认建议：占地范围不提供额外气，也不改变棋块连通。

### 8.2 控制范围

普通棋子：

- `ControlRadius = 1`
- 使用曼哈顿距离。
- 控制范围：`abs(dx) + abs(dy) <= 1`
- 包括棋子所在格。

强化棋子：

- `ControlRadius = 2`
- 使用曼哈顿距离。
- 控制范围：`abs(dx) + abs(dy) <= 2`

### 8.3 控制范围是否受地形阻挡

[待定]

默认建议：MVP 中控制范围不受地形阻挡，只按曼哈顿距离计算。

可选方案：

- 方案 A：不受阻挡，推荐用于 MVP。
- 方案 B：山峦阻挡控制范围。
- 方案 C：河流阻挡控制范围。
- 方案 D：不同地形会改变控制半径。

最终选择：

```text
[待填写]
地形是否阻挡控制范围：不受阻挡
```

### 8.4 归属判定

每次棋盘状态变化后重新计算所有地图块归属。

流程：

1. 清空所有地图块控制记录。
2. 遍历所有存活棋子。
3. 根据棋子控制半径计算可控制地图块。
4. 对每个地图块记录黑白双方控制来源。
5. 若只有黑方控制，则 `Owner = Black`。
6. 若只有白方控制，则 `Owner = White`。
7. 若双方均控制，则 `Owner = Contested`。
8. 若无人控制，则 `Owner = None`。

### 8.5 棋子所在格是否必定归属己方

[待定]

默认建议：不做特殊处理。棋子所在格也参与正常控制判定。如果双方都控制该格，则可为 `Contested`。

可选方案：

- 方案 A：按普通控制规则处理，推荐用于 MVP。
- 方案 B：棋子所在格永远属于棋子所属方。
- 方案 C：若敌方控制覆盖棋子所在格，则变为争夺。

最终选择：

```text
[待填写]
棋子所在格归属规则：按普通控制规则处理
```

### 8.6 争夺格

`Owner = Contested` 的地图块：

- 不属于黑方。
- 不属于白方。
- 不提供资源产出。
- 在传统占地胜负结算中不计入任何一方。

## 9. 资源规则

### 9.1 资源类型

MVP 资源类型：

- `Food`
- `Iron`

### 9.2 资源存储

每个阵营拥有一个 `ResourceWallet`。

规则：

- 资源数量不能小于 0。
- 消耗前必须检查资源是否足够。
- 非法操作不扣资源。

### 9.3 回合开始收入

在当前行动方回合开始时：

1. 遍历所有地图块。
2. 找到 `Owner` 等于当前行动方的地图块。
3. 若该地图块有产出，则把对应资源加入当前行动方资源。
4. `Owner = None` 或 `Owner = Contested` 的地图块不产出。

### 9.4 初始资源

初始资源由关卡配置决定。

默认建议：

- 黑方初始 `Food = 5`
- 黑方初始 `Iron = 0`
- 白方初始 `Food = 5`
- 白方初始 `Iron = 0`

最终选择：

```text
[待填写]
默认初始资源：按照默认建议
```

## 12. 回合流程

### 12.1 回合阶段

回合阶段：

- `StartTurn`
- `AwaitingAction`
- `ResolvingAction`
- `EndTurn`
- `GameOver`

### 12.2 当前行动方

- 游戏开始时，黑方先手。
- 黑方行动结束后切换至白方。
- 白方行动结束后切换至黑方。

### 12.3 完整回合数

[待定]

默认建议：黑方和白方各行动一次后，完整回合数 +1。也就是白方结束回合后 `FullRoundNumber += 1`。

最终选择：

```text
[待填写]
完整回合数增加时机：默认建议
```

### 12.4 每回合至少一个操作

[待定]

默认建议：每个回合至少需要完成一个非 `EndTurnAction` 操作，除非当前方没有任何合法操作。

可选方案：

- 方案 A：必须至少一个有效操作，推荐用于 MVP。
- 方案 B：允许直接跳过。
- 方案 C：跳过需要消耗资源或有惩罚。

最终选择：

```text
[待填写]
是否允许空过：必须至少一个有效操作
```

### 12.5 回合流程

1. `StartTurn`
   - 当前行动方获得资源。
   - 检查回合开始触发效果。
   - 进入 `AwaitingAction`。

2. `AwaitingAction`
   - 玩家或 AI 选择操作。
   - 操作包括 `PlacePieceAction`、`UpgradePieceAction`、`EndTurnAction`。

3. `ResolvingAction`
   - 检查操作合法性。
   - 扣除资源。
   - 应用操作。
   - 执行提子结算。
   - 执行占地重算。
   - 返回 `AwaitingAction`。

4. `EndTurn`
   - 检查胜负条件。
   - 若游戏未结束，切换行动方。
   - 必要时增加完整回合数。
   - 进入下一方 `StartTurn`。

5. `GameOver`
   - 锁定输入。
   - 显示胜负结果。

## 13. 非法操作规则

非法操作不会改变 `GameState`。

非法操作包括：

- 操作方不是当前行动方。
- 资源不足。
- 目标格不存在。
- 目标格不可放置。
- 目标格已有棋子。
- 放置后己方棋块无气且没有通过提子获得气。
- 升级目标不是友方棋子。
- 升级目标已经是最高级。
- 游戏已经结束。

非法操作结果：

- `ActionResult.Success = false`
- `ActionResult.ErrorMessage` 给 UI 显示。
- 不扣资源。
- 不推进回合。
- 不改变棋盘状态。

## 14. 胜利条件

### 14.1 传统占地

参数：

- `MaxRound`

规则：

1. 当完整回合数达到 `MaxRound` 后，在回合结束时结算。
2. 统计 `Owner = Black` 的地图块数量。
3. 统计 `Owner = White` 的地图块数量。
4. 数量多者获胜。
5. `Owner = None` 和 `Owner = Contested` 不计入任何一方。

### 14.2 平局处理

[待定]

默认建议：若双方占地数量相同，则判定为平局。

可选方案：

- 方案 A：平局，推荐用于 MVP。
- 方案 B：黑方胜。
- 方案 C：白方胜。
- 方案 D：比较资源总量。
- 方案 E：比较剩余棋子数量。

最终选择：

```text
[待填写]
平局处理：平局
```

### 14.3 夺旗

MVP 暂不完整实现。

参数：

- `FlagPositions`
- `RequiredHoldTurns`
- `MaxRound`

默认建议规则：

1. 若某阵营在自己的回合结束时拥有旗帜格，则该阵营对该旗帜的连续占领计数 +1。
2. 若旗帜格为 `None` 或 `Contested`，连续占领计数清零。
3. 若另一阵营拥有该旗帜格，则原阵营计数清零，另一阵营计数开始或增加。
4. 达到 `RequiredHoldTurns` 后获胜。
5. 超过 `MaxRound` 仍无人达成时，按关卡配置处理。

### 14.4 夺旗超时处理

[待定]

默认建议：超时后按传统占地数量结算。

最终选择：

```text
[待填写]
夺旗超时处理：夺旗超时则玩家失败
```

默认建议：白方使用 `RandomAIPlayerAgent`。

流程：

1. 枚举所有合法落子操作。
2. 若存在合法操作，随机选择一个执行。
3. 若无合法操作，执行 `EndTurnAction`。

### 15.2 AI 是否需要遵守每回合至少一个操作

默认建议：需要。若没有合法操作，则可直接结束回合。

## 16. 地形规则

MVP 地形：

- `Plain`
- `Mountain`

### 16.1 Plain

默认：

- 可放置棋子。
- 可提供气。
- 可被控制。

### 16.2 Mountain

[待定]

默认建议：MVP 中 Mountain 不可放置棋子，但可以被占地控制，可以提供资源，也可以提供气。

可选方案：

- 方案 A：不可放置，但可控制、可产出、可提供气，推荐用于 MVP。
- 方案 B：不可放置，不可控制，不产出，不提供气。
- 方案 C：可放置，但费用增加。

## 17. 规则结算时机汇总

### 17.1 放置棋子成功后

依次执行：

1. 扣除资源。
2. 放置棋子。
3. 执行提子结算。
4. 若非法则回滚。
5. 重新计算占地。
6. 更新 UI。

### 17.2 强化棋子成功后

依次执行：

1. 扣除资源。
2. 修改棋子类型。
3. 重新计算占地。
4. 更新 UI。

### 17.3 回合开始

依次执行：

1. 当前行动方获得资源。
2. 更新 UI。
3. 等待操作。

### 17.4 回合结束

依次执行：

1. 判断胜负。
2. 若未结束，切换行动方。
3. 必要时增加完整回合数。
4. 进入下一方回合开始。
