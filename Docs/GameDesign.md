# GameDesign.md

## 1. 项目概述

- 开发环境：Unity
- 游戏类型：2D 俯视角回合制战棋游戏
- 核心玩法：在正方形网格地图上放置棋子，使用类似围棋的「气」与「提子」规则争夺地块，通过占有地块获得资源，并通过不同关卡条件取得胜利。
- 对局阵营：黑方与白方。
  - 黑方：默认玩家方。
  - 白方：默认电脑方。
- 先手：黑方先手。

## 2. 设计目标

本游戏希望结合以下体验：

1. 围棋式的区域压迫与生存判断。
2. 战棋式的回合推进和资源规划。
3. 可重复挑战的关卡设计。
4. 简洁规则下的策略变化。

## 3. MVP 范围

第一版最小可玩版本只实现以下内容：

- 单张测试地图加载。
- 地图使用 Unity Tilemap 作为初始数据来源和显示层。
- 逻辑地图使用 `GridModel` 独立维护。
- 两种地形：`Plain`、`Mountain`。
- 两种资源：`Food`、`Iron`。
- 两方阵营：`Black`、`White`。
- 一种普通棋子：`Normal`。
- 四方向气规则。
- 放置棋子。
- 提子。
- 占地重算。
- 回合切换。
- 回合开始资源产出。
- 传统占地胜利条件。
- 简单 UI：显示当前方、资源、回合数、选中格信息。
- 白方使用简单 AI：优先 `RandomAIPlayerAgent`，之后可替换为 `GreedyAIPlayerAgent`。

## 4. MVP 暂不实现

以下内容不进入第一阶段，避免 Codex 一次性处理过多系统：

- 强化棋子完整功能。
- 河流特殊效果。
- 山峦阻挡控制范围。
- 复杂 AI。
- 存档系统。
- 联机系统。
- 战斗动画。
- 多关卡选择界面。
- 夺旗模式完整实现。
- 特殊棋子技能。

## 5. 核心循环

一局游戏由若干完整回合组成。每个完整回合包含黑方行动和白方行动。

流程：

1. 读取关卡配置。
2. 加载关卡指定地图。
3. 从 Tilemap 生成逻辑地图 `GridModel`。
4. 根据关卡配置放置初始棋子。
5. 初始化双方资源。
6. 黑方开始行动。
7. 当前行动方回合开始时获得资源。
8. 当前行动方执行至少一个操作。
9. 当前行动方结束回合。
10. 判断胜负。
11. 未结束则切换到另一方。
12. 重复直到游戏结束。

## 6. 地图系统概念

地图由一系列正方形地图块组成。每个地图块具有：

- 坐标。
- 地形类型。
- 资源产出类型。
- 资源产出值。
- 当前归属。
- 是否可放置棋子。
- 当前是否被棋子占据。

地图在 Unity 中以 Tilemap 形式保存，但运行时规则不直接依赖 Tilemap。

## 7. 棋子系统概念

棋子类似围棋棋子，是双方在棋盘上创建和放置的单位。

棋子具有：

- 所属方。
- 棋子类型。
- 所在坐标。
- 是否存活。
- 控制半径。

棋子的生存受「气」影响。棋子或同阵营相连棋子组成的棋块若无气，则会被提走。

## 8. 占地系统概念

棋子会影响周围地图块的归属。

默认规则：

- 普通棋子控制自身格和四方向相邻格。
- 强化棋子未来可控制更大范围。
- 双方同时控制的地图块为争夺状态，不属于任何一方。
- 只有明确归属于一方的地图块提供资源。

详细规则见 `Docs/Rules.md`。

## 9. 资源系统概念

资源是单场游戏内可跨回合累积的货币。

资源用于：

- 生成新棋子。
- 强化棋子。
- 未来可扩展为释放技能、修建设施、改变地形等。

默认资源类型：

- `Food`：普通资源。
- `Iron`：稀有资源。

## 10. 关卡系统概念

关卡是一场预设好的、可重复进行的游戏。

关卡定义包括：

- 所用地图。
- 初始棋子位置。
- 初始资源。
- 胜利条件类型。
- 最大回合数。
- 特殊目标点，例如旗帜点。
- 白方 AI 配置。

建议使用 `LevelDefinition` ScriptableObject 管理关卡数据。

## 11. 关卡类型

### 11.1 传统占地

在指定完整回合数后结算双方占有地图块数量，占有数量更多的一方获胜。

### 11.2 夺旗

在指定回合数内，占领指定地图块并连续保持若干回合后获胜。

夺旗模式第一阶段可只保留数据结构和接口，不实现完整玩法。

## 12. 玩家操作

MVP 阶段支持：

- 放置普通棋子。
- 结束回合。

后续扩展：

- 强化友方棋子。
- 使用特殊技能。
- 地形交互。
- 消耗资源生成特殊单位。

## 13. 用户界面需求

MVP UI 只需要能验证核心玩法：

- 显示当前行动方。
- 显示当前完整回合数。
- 显示双方资源。
- 显示选中地图块坐标、地形、产出、归属、是否有棋子。
- 点击空格时尝试放置棋子。
- 点击结束回合按钮结束当前方回合。
- 游戏结束时显示胜负结果。

## 14. 设计原则

- 规则应优先清晰，而不是一开始追求复杂。
- 所有核心规则都应可用单元测试验证。
- Unity 场景负责显示和输入，不负责核心判定。
- 未来扩展应通过新增规则服务、行动类型、胜利条件或 AI 策略完成。
